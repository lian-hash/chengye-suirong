# 城野随行 —— 模拟数据导入 uniCloud 云数据库

把 `mock-data` 里的 39 条模拟数据灌进云数据库，让小程序脱离 Mock 也能跑真实数据。

| 集合 | 条数 | 说明 |
|---|---|---|
| users | 4 | C 端用户（含 admin / ent 后台账号） |
| packages | 3 | 套餐（春/夏/秋三季） |
| sites | 3 | 场地 |
| equipments | 7 | 装备库存 |
| orders | 9 | 订单，**覆盖 7 态 + 已取消** |
| deliveries | 6 | 配送记录 |
| reviews | 2 | 评价 |
| logs | 5 | 操作日志 |
| **合计** | **39** | |

---

## 为什么用 JSON 而不是直接导 CSV

控制台直接导 CSV 会把类型全弄成字符串：

- `onShelf` → `"True"`（字符串）而不是布尔 → 云函数 `where({ onShelf: true })` 查不到
- `equipRefs` → `"[{...}]"`（一整串）而不是数组 → 装备扣减逻辑失效

所以先跑一次转换脚本，生成类型正确的 JSON：

```bash
cd mock-data
python csv_to_cloud_json.py
```

产出 `mock-data/cloud-import/*.json`（8 个文件），已修正为：
`onShelf: true`、`isBatch: false`、`equipRefs: [...]`、`price/quantity/amount: 数字`。

## 方式 A：控制台导入（推荐，零代码）

1. 打开 [uniCloud 控制台](https://unicloud.dcloud.net.cn/) → 选你的服务空间 → **云数据库**。
2. 依次选中 8 个集合（没有就先「创建集合」，名字照抄上表）。
3. 每个集合点 **导入** → 选择 `cloud-import/` 下对应的 `.json` 文件 → 确认。
4. **按依赖顺序导入**：`users / packages / sites / equipments` → `orders` → `deliveries / reviews / logs`。

> 时间字段是 ISO 字符串（如 `2026-04-01T10:00:00`），与现有 `seed.js` 保持一致，云函数按字符串比较可正常工作。

---

## 方式 B：HBuilderX 运行云函数

1. 在 HBuilderX 里右键 `uniCloud/cloudfunctions/initDB` → **上传部署**。
2. 右键 → **运行云函数**，参数填：

```json
{ "action": "import", "collection": "packages", "docs": [ ...粘贴 packages.json 内容... ] }
```

3. 想复位演示数据，加 `"clear": true`：

```json
{ "action": "import", "collection": "orders", "docs": [ ... ], "clear": true }
```

---

## 方式 C：本地脚本一键灌（需 URL 化，最省事）

前置：`initDB` 云函数开启 **URL 化**，拿到地址（形如
`https://xxxx.service.tcloudbase.com/initDB`）。

```bash
cd mock-data

# 1) 先测连通性 + 看现有条数
node import_to_cloud.js --url https://xxxx.service.tcloudbase.com/initDB --stats

# 2) 灌全部 8 个集合（追加）
node import_to_cloud.js --url https://xxxx.service.tcloudbase.com/initDB --all

# 3) 演示前复位（先清空再灌）
node import_to_cloud.js --url https://xxxx.service.tcloudbase.com/initDB --all --clear

# 4) 只重灌某一个集合
node import_to_cloud.js --url https://xxxx.service.tcloudbase.com/initDB --only packages --clear
```

也可以把地址存进环境变量，省得每次敲：

```bash
export UNICLOUD_HTTP_BASE=https://xxxx.service.tcloudbase.com
node import_to_cloud.js --all --clear
```

脚本会按顺序灌入并在结束后打印各集合最终条数，便于核对。

## initDB 云函数支持的动作

| action | 参数 | 作用 |
|---|---|---|
| `init`（默认） | — | 幂等写主数据种子 + 补全 admin/ent 账号，可反复执行 |
| `import` | `collection`, `docs`, `clear?` | 批量灌入指定集合 |
| `stats` | — | 查 8 个集合条数（验证导入结果） |
| `clear` | `collection`, `confirm: true` | 清空集合（危险，需显式 confirm） |

集合名受白名单保护（只允许上表 8 个），误传会被拒绝。

---

## 导入后：让小程序读真实数据

⚠️ **现在小程序是 Mock 模式，不会去读云数据库。** 灌完数据后要切换：

1. 编辑 `uniapp/utils/request.js`：
   - `FORCE_MOCK = true` → 改成 `false`
   - `UNICLOUD_ENV = ''` → 填上你的 uniCloud 空间标识
2. 在 HBuilderX 里把 `uniapp/uniCloud/cloudfunctions/` 下的云函数**全部上传部署**。
3. 重新编译微信小程序：`npm run build:mp-weixin`（记得带 `NODE_OPTIONS=--openssl-legacy-provider`）。

同理，Web 管理后台走 `web/src/utils/request.js`，把 `FORCE_MOCK` 置 false 并填好 URL 化地址即可。

## 常见问题

**Q：导入后前端还是显示 Mock 数据？**
A：检查 `FORCE_MOCK` 是否已置 `false`，以及云函数是否已上传部署。

**Q：`clear` 报「需显式传 confirm」？**
A：防误删保护，参数里加 `"confirm": true` 即可。

**Q：orders 里的 `_id` 怎么办？**
A：不用管。导入时不带 `_id`，uniCloud 会自动生成；业务查询用的是 `orderId` / `packageId` 等业务主键。

**Q：想恢复到最初的种子数据？**
A：跑 `initDB` 的 `init` 动作，它是幂等的（集合非空就跳过）；需要强制复位就先 `clear` 再 `init`。
