| 当前模式 | **仅 Mock 模式**（`uniapp/config/unicloud.js` 与 `web/src/config/backend.js` 均为 `FORCE_MOCK=true`），不接云、不部署 |

### 1.1 接口返回约定

- 统一结构 `{ code, message, data }`，`code=0` 视为成功。
- 错误码：`0` 成功；`4001` 参数错误；`4002` 订单状态非法；`4003` 资源类失败（套餐下架/场地约满/装备不足）；`4004` 无权限；`4009` 重复操作；`5000` 系统异常。
- 订单状态机 7 态：`待支付 → 已支付 → 配送中 → 布置中 → 使用中 → 已回收 → 已完成`。
- 配送推进语义（对齐 uniCloud `delivery` 云函数）：`dispatch(已支付→配送中)`、`setup(配送中→布置中)`、`recover(布置中|使用中→已完成)`。

### 7.1 明确的实现缺口

- **缺口 1 —— 小程序没有「取消订单」「退款」入口**：后端 `order.cancel` 与 `order.refund` **已实现**，但 C 端 `uniapp/services/order.js` 只暴露 `create / pay / list / detail / track`，`uniapp/services/review.js` 只暴露 `submitReview`，10 个页面（`index / packageDetail / siteSelect / orderCreate / orderPay / orderList / orderDetail / review / mine / login`）中也**没有任何页面调用**这两个动作。结论：取消与退款在小程序侧**未实现**，只能在 Web 后台操作（或后续补齐入口）。对应样例 TC-D-10 当前为「阻塞」。
- **缺口 2 —— 按架构不在小程序内的能力**：P4 配送调度（`delivery.*`）、P5 装备管理（`equipment.*`）、P6 财务统计与操作日志（`finance.stats` / `log.list`）、B端批量下单（`order.batchCreate`）、套餐与场地的增删改与上下架（`upsertPackage` / `setShelf` / `upsertSite`）、用户角色调整（`user.updateRole`）—— 这些按架构归属 **Web 后台**（B端/管理员），小程序内不提供，属预期范围，非缺陷。
